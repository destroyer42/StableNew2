## Baseline

- Product v2.6 MVP, release proof complete (PR-MVP-090). Remote `destroyer42/StableNew2`, default branch `main`.
- Canonical path: `Intent -> Compiler -> NJR -> JobService -> Queue/Repository -> PipelineRunner.run_njr -> Handler ->
  Artifacts/History`. Fresh work is queued, the NJR is immutable, lifecycle belongs to the SQLite repository, replay creates
  a new NJR with lineage, and the GUI/controllers create no second runner. Authority: `AGENTS.md`, `docs/ARCHITECTURE_v2.6.md`.
- Interpreter: CPython 3.14 standard-GIL only. Windows runtime pins: `constraints/windows-py314-cu130.txt`; dev/CI tools:
  `requirements-dev.txt`. Managed Forge Neo (`config/managed_forge_runtime.json`) and managed Comfy
  (`config/managed_comfy_runtime.json`) are pinned separately and never share the application environment.
- Single-node, same-process execution. Production video backends: native SVD XT and the Comfy workflows the catalog marks
  `approved` (today Wan2.2 I2V-A14B 4-step 1.0.0, TI2V-5B 1.2.0 and the frames-out 1.3.0, and the 720p TI2V-5B workflow 1.0.0); every other workflow is experimental: Queue warns and records the job's own opt-in (N1, warn don't block; unqualified Forge checkpoints also run with a why-and-fix warning; real blocks stay; `AGENTS.md` section 2). N1b: the SDXL-only features (Learning Embedding, LoRA Composition, Prompt Slot, Two-Axis, Model Comparison and Matrix; ControlNet; Review mask, outpaint and guided passes) run an unclassified checkpoint with a warning, count completed queue runs of the same checkpoint, operation and backend as verified ("ran N times here"; eligibility only, never recommendation evidence), and refuse a positively identified other family (`docs/Subsystems/Learning/LEARNING.md` section 3.19).

## What `main` enforces (all PRs)

- `main` is protected: a PR is required, force pushes and deletion are blocked, the owner may bypass. Required checks:
  `required`, `full-suite` (the sharded census) and `windows`. Docs-only changes take a cheap path.
- `required` runs: repository completeness, controller-surface ratchet, `ruff check .`, mypy smoke, **ratchets** (below), the controller Tk import
  boundary, isolated collection and the required smoke. Run locally with `python tools/ci/run_pr_gate.py` (`--parity` adds the tests the change affects, as the hosted runner sees them; `--full` adds the sharded census) after
  `pip install -r requirements.txt -r requirements-dev.txt`.
- Ratchets only allow recorded debt to shrink (baselines under `tools/ci/`; `python tools/ci/ci_truth.py --ratchets` prints the current figures): whole-`src` strict mypy, unformatted files, blind/silent excepts in `src` (BLE001, S110, S112), thread and layering rules (daemon threads, raw threads, utils importing upward, controller importing the GUI), plain truncating file writes outside `atomic_io` (allowlist in `tools/ci/run_architecture_ratchets.py`), and the four controller line ceilings. Figures are not repeated here, so parallel ratchet-lowering PRs don't conflict; a figure stated here must still match the baseline.
- Workflows are SHA-pinned, the default token is read-only, and no workflow runs fork code with secrets.
  Flaky tests are repaired or quarantined with an owner and expiry (`tests/quarantine/README.md`).
