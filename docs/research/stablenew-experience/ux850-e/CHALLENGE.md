# Same-author distinct-method challenge

This is a **same-author, distinct-method challenge**, not an independent reviewer sign-off. No agents or other chats participated. Independent review/owner acceptance remains unknown. The package is a Focused research assessment; A's partial Comprehensive scope stays partial.

## Acquisition methods

Pass A traces current production service/adaptor composition, policy/identity/frozen-study/readback/profile APIs and native stores, then maps owner directions to bounded mechanisms. Existing A–D evidence is reused only after exact `src/` tree and relevant source/test/config/qualification path comparison, not because summaries were accepted.

Pass B obtains different evidence: Python AST extracts **23 selected existing negative test bodies**, exact assertions and call names into an external manifest without imports or execution; then compares those contracts with source reduction/commit points. It also searches current `src/` for AI-summary consumers (only definitions/internal doc reference found), checks shipped manifest data, and walks the actual import merge and profile cohort-reduction expressions. T01–T23 exact test names/lines are in [SOURCE_INDEX.md](SOURCE_INDEX.md). Search absence is bounded evidence, not proof no dynamic/plugin caller can exist. No test pass, live reproduction, independent author or scientific validation is invented.

## Focused critical controls and six evidence dimensions

| v1.2 control | Evidence inspected / negative path | Limit |
|---|---|---|
| Governance | Exact isolated base/branch and shared settings fingerprint; remote main read via GitHub connector after shell DNS failure | Protection/bypass enforcement not refreshed; coordinator must verify before integration |
| CI truth | Docs-only routing and CI-truth/evidence checker source; cheap local checks | No hosted E run, failed-run sample or current enforcement verdict |
| Production composition | AI integration, existing next-test and publication adapters, Learning canonical submission and accepted D spine | No app construction/GUI execution; alternative injection/dynamic reachability unverified |
| Process ownership | Strict production AI config, observation/yield/refusal contracts, owned subprocess boundary | No Windows handle/containment/current physical evidence; no external process actions |
| Persistence | Latest rating keys, immutable Learning publish, catalog snapshots/pointer, write-ahead IDs and failure assertions | Not an every-store/corruption/multiprocess audit; no operator data opened |
| Dispatch/recovery | T14/T15 negative contracts and batch source; canonical job authority retained | No live backend/fault/cancel or campaign-stop race proof |
| Untrusted inputs | AI validators/closed IDs, catalog/source lookup schema, privacy bounds, qualification gates | Not a parser/supply-chain security clearance; independent review absent |
| Operator reachability | Current handlers/routes plus accepted unchanged A/B/C | Actual Tk/Windows/DPI/accessibility/operator benefit unverified |

For every C-row, **code existence** is the anchored mechanism; **GUI reachability** is static binding evidence or “no current surface”; **contract correctness** is only the cited static/accepted evidence scope; **task usefulness** is an explicit hypothesis/low-cost alternative; **usage frequency/denominator** and **sustainable maintenance/inference cost** are unmeasured. Existing does not imply all six dimensions pass. Qualification-dependent/experimental/blocked rows have no demonstrated general workflow correctness or payoff. This is an explicit evidence boundary, not a numeric scoring exercise.

Framework lesson: capability names such as “Learning,” “AI-ready,” “qualification,” or “profile” are too broad to act as evidence categories. Assess the exact consumer, identity and permitted consequence; test assertions can falsify overclaims without running a model, but cannot replace physical/scientific/operator evidence. A future independent reviewer should focus first on G6/072, campaign approval/races and import dependence, with exact updated sources rather than repeat the accepted inventory.
