# PROPOSED handoff and context-preservation contract

This is an interaction specification, not a new payload/schema or implemented transaction service. Existing partial mechanisms are named below. Generic guard/rollback behavior needs future implementation within existing owners; do not claim all current routes already have it.

## Common identity and replacement rules

Keep distinct: **source identity** (recorded job/artifact or explicit external-file provenance), **editable destination draft/revision**, **preview snapshot/approval**, and **new submitted NJR ID**. A navigation event has no executable identity. Pack identity is copied only for an actually PromptPack-sourced path; an external image never receives a guessed pack/job parent. Byte-identical files are not independent research samples or interchangeable logical assets.

Before a proposed incoming placement: resolve/validate destination, snapshot ordered sources and their provenance, inspect destination unsent work, and summarize preserved/copied/reset fields. If replacement is needed offer **Replace unsent work / Cancel**. Cancel changes neither source query/selection, destination draft/preview nor navigation. Replace is deliberate consent to replace that unsent intent, not to overwrite a saved document, delete media, cancel an admitted job or authorize execution. Offer the destination's existing explicit Save/Save As before replacement when applicable; do not imply universal recoverable backup. If keeping the draft safely requires a new recovery store, retain Cancel and gate that extension.

Only after successful placement should the proposed generalized flow navigate and acknowledge the target. Revalidate target lifetime/revision when an async handoff returns. Changed destination, shutdown, missing files or validation failure leaves both contexts intact and explains how to retry manually. Never issue a blind compensating write over a newer draft. Existing `route_image_to_video_workflow` navigates before setting and does not supply this generalized transaction/unsent-work guard; E67 is a foundation, not proof of full behavior. Review and History variation already have explicit unsent-work guards (E67/E78). All source anchors resolve in [A's index](../ux850-a/SOURCE_INDEX.md).

## Persistence and return behavior

| State class | Owner / lifetime | Navigation and handoff requirement |
|---|---|---|
| Temporary draft / selection / pinned presentation proposal | Current GUI intent owner (AppStateV2 and existing workspace state); no new global shadow store | Switching views does not submit or claim persistence. New durable recovery/pins need an approved policy |
| Saved pack, startup defaults, Photo/Storyboard draft | Existing corresponding store, explicit supported save scope | Copy/application does not overwrite saved source; preserve version/conflict/refusal behavior |
| Approved research configuration | Existing frozen study/batch + recorded approval identity | Cross-workflow use copies values/provenance; never transfers permission to run a changed study/campaign |
| Frozen executable job and lifecycle | NJR plus JobRepository/JobService | New work has new identity/lineage. GUI return links project current repository state; they do not resume by rebuilding jobs |

Return to source restores **in-session** browse position/selection where still valid. If sources changed, retain filters and show unavailable rows rather than select a substitute. Cross-restart restoration is limited to existing stores and tab selection, with clear unknown/unsaved status. A submitted job continues under canonical ownership even if the draft is replaced or its tab is hidden.
