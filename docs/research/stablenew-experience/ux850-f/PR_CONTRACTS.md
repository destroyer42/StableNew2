# Proposed coherent implementation PR contracts

These six candidates are **not authorized implementation**. P1 is the first recommendation; P2 is the default successor; P3–P6 are alternatives/conditional work, not six mandatory phases. Each future package starts in a fresh top-level session after owner selection, rechecks exact SHA/source/diff and its accepted scope, and removes already-delivered work. Entry paths are verified at F base in [SOURCE_INDEX.md](SOURCE_INDEX.md); existing tests are inspection/extension entrypoints, **not fresh passes**. New tests/cases are explicitly future work.

## Shared contract applying to P1–P6

- **Runtime/authority:** retain Intent → compiler → immutable NJR → JobService → SQLite queue/repository → `PipelineRunner.run_njr` → handler → artifacts/History. GUI captures intent and projects state; no new queue, runner, lifecycle, cancellation/process authority or backend payload builder. No controller ratchet increase; cohesive projection/service changes may require lowering the ceiling if a ratcheted controller shrinks. Do not turn allowed filenames into an exhaustive owner-required list.
- **Failure/rollback:** keep authoritative original records/files and admitted IDs. A failed view/query/refresh yields visible unknown/error and an explicit retry of the read; never compensate by saving over a newer draft or resubmitting work. On failed acceptance keep the candidate unintegrated and repair within the bounded package; after integration, reverting the feature diff needs current owner authorization for that target. Code rollback never restores older user data. No destructive migration is part of these six candidates.
- **Token-Efficient Validation Plan:** one source acquisition; focused deterministic changed-contract tests using temporary state and fake services first; one aggregate review and bounded batched repair; one late `python tools/ci/run_pr_gate.py` for executable changes, then exact-head hosted Python 3.14 required/census/windows verdict per current policy. Reuse unchanged evidence; no repeated full gate after prose-only changes. No real backend/model/GPU/network or user store in tests. Separately authorize actual Windows/operator or physical evidence only if required by the accepted outcome.
- **Completion:** implementation diff and named deterministic evidence can accept the bounded code contract; actual GUI behavior remains NOT TESTED until observed, qualification N/A unless an identity-applicable verdict is explicitly part of an authorized package. No universal physical-generation gate. PR body records exact source/evidence, held behavior, model/effort/repair passes and measured usage; predictions below are planning assumptions, never actuals or budgets.
- **Stop:** higher class, new persistence/consent/statistics/platform/hardware policy or runtime ownership ambiguity → owner decision. Do not expand a presentation package to resolve a known G gate. Security review uses existing triggers if actual changes cross them; a source path in this research is not security sign-off.

## P1 — protect unsaved PromptPack work during explicit Load

**Outcome / trigger:** with edited working pack A, choose B and activate Load or double-click. Current handler replaces A without a dirty guard; proposed handler offers the existing New-style discard/cancel choice. Cancel preserves A. This closes one bounded omission under 008 and preserves 005, not general draft recovery or application-close protection.

**Source/test entrypoints:** `src/gui/views/prompt_tab_frame_v2.py` (`_on_new_pack`, `_on_load_selected_pack`, Load command and double-click binding); `src/gui/prompt_workspace_state.py` (`load_pack`, dirty setters). Reuse `tests/state/test_prompt_workspace_state.py`, `tests/gui_v2/test_prompt_workspace_state_negative.py` and Prompt fixtures in `tests/gui_v2/test_prompt_authoring_540.py`; add focused handler/binding tests rather than treating current state-only tests as guard coverage. PromptPack schema/native Save remains owned by existing storage/model code.

**Observable acceptance and negatives:** dirty Load decline or window-close leaves current pack object/content, dirty flag, editor/slot and existing Preview/admitted jobs unchanged; no file write/load or programmatic navigation/refresh. A candidate selected in the pack list may remain selected: list selection is not the currently edited document and must not auto-load. Accept loads exactly once and refreshes current editor through the existing path. Clean Load retains current behavior. Same-pack reload is still replacement and receives the dirty guard. No selection or invalid visible index preserves existing error/refusal without replacement; malformed/missing pack fails without dropping current draft. Verify both button and double-click reach the guarded method, and repeated activation cannot bypass it. Keep New's behavior unchanged. Native Save/Save As remains the deliberate way to retain edits; no silent save.

**Failure/rollback:** parse/load failure leaves old workspace intact (current state loads before assignment). Add negative tests for this ordering. Scope excludes general snapshot rollback, shutdown guard, TXT import replacement, arbitrary pack switching and persistent recovery. If discovering that editor buffers bypass dirty tracking is required for this acceptance, assess the concrete in-scope path; broader authoring semantics require re-scope. Shared rollback contract applies.

**Dependency/owner gate:** owner selects this precise replacement confirmation; no new durable semantics and no decision on generation G2. At future start confirm source guard still absent and no already-wired wrapper fixes it; otherwise remove P1. No dependency on P2–P6 or R1.

**Execution Profile + Model/Reasoning Recommendation:** Narrow / Local for eventual Tk evidence; **Codex GPT-6.1 Sol Medium / Claude Code Sonnet 5.5 High**. Known handler/state omission, small regression surface and current fixtures make a higher architecture tier unnecessary; the recommendation includes binding/negative validation and retry risk. Expected about **2M cache-read / 15k output**, planning only; no delegated hard part.

**Controller Surface Assessment:** no controller/coordinator behavior expected; use existing view/state owner, not AppController. Architecture unchanged. **Token-Efficient Validation Plan:** isolate fake-dialog/loader spies and pure state regression first, then Prompt contract subset and shared late code gates. Actual dialog/keyboard proof is a separately authorized synthetic Windows trial; no generation is necessary. Documentation impact: update the living PromptPack UX description only if current protection truth changes.
