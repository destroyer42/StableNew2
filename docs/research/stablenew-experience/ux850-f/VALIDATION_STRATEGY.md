# Integrated deterministic, Windows and qualification strategy

Validate each claim at the layer that can establish it. Use existing [testing authority](../../../Subsystems/Testing/TESTING_AND_CI.md), [coding/testing levels](../../../StableNew_Coding_and_Testing_v2.6.md), `pyproject.toml`, existing mocks/fakes and retained operator/qualification harnesses. No new universal orchestration harness, acceptance registry or qualification status is needed. All cases below are **future strategy**, not tests executed by F.

| Layer | Method / identity | Can accept / cannot establish |
|---|---|---|
| Documentary applicability | Accepted Git artifacts/source blobs and local links; F's coverage/dependency checks | Coherent research and source applicability; no functional behavior or operator benefit |
| Pure/domain deterministic | Temporary pack/study/Storyboard/media records, typed projections and fixed inputs | State transitions, identity/negative/rollback rules under fakes; not live GUI, OS durability or generated quality |
| Mock integration / Tk construction | Existing application composition/fake service and Tk fixtures, no real backends/user stores | Correct callback/binding/service/admission boundary in that harness; construction is not keyboard/DPI/UIA proof |
| Required code CI | Exact PR head, Python 3.14 required/census/windows per current workflow; inspect every job conclusion | Integration verdict for executed suites; skipped lanes/cases remain skipped, hosted Tk is not physical Windows operator acceptance |
| Separately authorized Windows/operator | Frozen exact app SHA, isolated roots, synthetic inputs, recorded OS/client/DPI/theme/key/UIA conditions | Observed task/accessibility behavior and measured task denominator for that setup; no statistical benefit/general hardware claim without a defined comparator |
| Separately authorized physical qualification | Existing applicable authority/harness, frozen exact models/runtime/config/data/hardware and owner-accepted verdict | Only identity-applicable formally accepted scope. Static prototypes, CI or a successful generation do not independently qualify anything |

## Separately authorized Windows acceptance packet

Before execution, owner authorization names exact package/SHA, input roots/artifact identities, allowed UI/process actions, isolated settings/state and evidence destination. Use existing `tools/operator_journey/golden/` or appropriate existing operator harness after verifying fit. No backend launch/restart/cancel, inference/download or external-process adoption is implied by GUI authorization. A physical generation requirement, if any, receives its own exact authorization and applicable qualification procedure.

Record physical display/work area and client rectangle, Tk client dimensions, scale and monitor DPI, process/thread DPI-awareness, `tk scaling`, font metrics, window state/theme/High Contrast, screenshot capture awareness, OS/runtime and app SHA. Reuse [C's six-row L/P matrix](../ux850-c/WINDOWS_ACCESSIBILITY.md): 1280×680 compatibility and 1280×760 comparison, each at 100/125/150%. Holding logical client size and holding physical client size are distinct interpretations; 12 declared cells have coincident 100% pairs. P stresses are not new minimum support guarantees. Missing hardware/cell → unavailable, never substitution silently labelled pass. Simulated font growth is not OS DPI evidence; cross-monitor testing is an additional stress.

For the selected route, measure essential control bounds/label fit and actual Tab/Shift+Tab/Enter/Space/Escape traversal, nested scroll reveal, focus return and no pointer-target movement. Inspect actual UIA/screen-reader names/values/states/announcement and High Contrast. Preserve user data in temporary roots; no production settings mutation for a test. Record unsupported essential operations/manual alternatives and route platform decisions to owner; do not assume Qt is necessary or sufficient.

Use B's fixed ordinary task and one advanced/recovery variant as appropriate: structured pack→Preview; edit/compare/return; Storyboard→assembly intent; find a supported prior result; study→ratings→profile→explicit Create reuse. With fake backends, stop at captured canonical admission and label results simulated. Record attempted/completed tasks, unintended replacements/submissions, wrong routes, assistance, save-scope/warning discovery and time per task. Proposed safety acceptance is zero unintended execution/replacement/data loss in the defined trials; one failure fails that case. No improvement percentage is claimed without a frozen baseline/comparator and adequate method. Report all trials, not only successes. C's optional input-acknowledgement performance proposal remains a proposal unless separately selected and measured.

## Qualification and evidence freeze

Ordinary deterministic authoring/readiness fixes need no universal GPU acceptance. Exact masked-output quality, new temporal/audio models, model resource capacity and evaluator performance do. Before those runs freeze model/checkpoint hashes, runtime/backend/workflow, effective settings and prompt adaptation, data/artifacts/preprocessor/rubric, hardware/driver/OS and acceptance/stop rules. Distinguish requested/compiled/dispatched/backend-reported/observed evidence. Obtain owner acceptance through the existing authority, keep negative/inconclusive outcomes and applicability limits, and retain the post-runtime evidence freeze rule. Future method changes must not retroactively reclassify old observations or lower thresholds after output.

## Program checkpoint / regression and token discipline

At each accepted package: exact diff/SHA + applicable required CI + preserved originals + four-way completion + affected canonical truth check. Reorder on actual evidence; do not rerun broad application suites for docs-only follow-up or recreate a delivered subsystem. For executable packages run focused tests then one prescribed late gate and required hosted verdict. Inspect skips separately. A new unresolved class or material owner choice stops that package with a ready decision packet, not an unbounded repair loop. F itself uses cheap documentation checks only, as recorded externally.
