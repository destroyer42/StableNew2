## Adjusted recommendation and sensitivity

**Final:** W1 P1 → default W2 P2; P3/P4/P5 can move ahead on owner task evidence, P6 only on current reproduction. This lowers the first outcome's coupling while keeping it independently useful. R1–R5/H3/H4 remain conditional. No new threat forces a program-wide stop; a verified unmitigated threat would override this order. If Load is already guarded at implementation start, remove P1. The framework adjustment is to distinguish a narrow omission from its much larger product direction, test production bindings separately from helper correctness, and require an explicit “already delivered?” check per proposed outcome. Remaining bias: one author selected paths and assertions, no exhaustive durable-store/security audit or failed-run/Windows probe, and no operator denominator. Independent review or actual task evidence may change the order; none is invented here.
