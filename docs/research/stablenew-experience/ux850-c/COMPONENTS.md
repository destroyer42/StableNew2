# Reusable PROPOSED component and interaction specification

All layout below is proposed. **Existing foundation** means a capability/source owner exists at C's base, not that this composed presentation is already implemented. Source references resolve in [TK_FEASIBILITY.md](TK_FEASIBILITY.md); source-wide implementation classifications stay in [A](../ux850-a/DECISION_TRACEABILITY.md). B's [verbs/freshness](../ux850-b/INTERACTION_SEMANTICS.md) and [H1–H10](../ux850-b/HANDOFFS.md) govern every component.

## Error, loading, empty and notification patterns

| Condition | Required message/action | Preservation and recovery |
|---|---|---|
| Loading/preview/query pending | “Loading [named scope]”; keep previous content labelled stale or show skeleton; explicit pending action, no invented percentage | Latest request wins; keep input editable unless its owning action truly requires a lock. A cosmetic spinner is not a job lifecycle state |
| Empty source | “No recorded outputs in this source”; offer its existing create/open/import route | Do not silently scan the filesystem or load hidden content |
| Zero filter matches | “No matches for these filters”; Clear Filters and current bounded-search limits | Preserve source and selection context where valid; distinguish empty source |
| Media hidden / file missing | “Hidden by visibility policy” / “Recorded file unavailable” respectively; deliberate Show only when policy permits | Preserve job/artifact record. Verify/relink only through existing owner; no filename substitution |
| Invalid field / compatibility refusal | Name control, requested value, applicable restriction and supported correction; focus first invalid field after explicit validation | Keep all other intent; no silent value coercion disguised as accepted intent |
| Save failed / save succeeded but refresh failed | “Not saved” versus “Saved [identity/revision]; refresh failed” | Never encourage duplicate save/publication when durable write is already established; offer reopen/refresh via owner |
| Partial/unknown admission | Exact admitted IDs and exclusions if known; “Outcome unknown — check recorded jobs” otherwise | Respect current per-contract atomicity; no automatic retry of ambiguous dispatched POSTs |
| Backend unavailable / execution failure | Current canonical hold/failure and Details; safe existing recovery route | No external process adoption, kill/restart or hidden inference. Explicit Replay/eligible Resume creates a new NJR |
| Conflicting/stale research evidence | Conditions, scope, saved observations and missing evidence; create-only follow-up if supported | Do not infer sufficiency from confidence or auto-publish/apply a profile. Pending 072 remains visible |

## Asynchronous presentation and lifetime

Use the root's existing UiDispatcher and GUI-owned state/projection path. File enumeration, metadata, thumbnail decoding and model/profile/evidence work belongs behind existing background query/services, never in widget layout callbacks. Each response must be tied to its source identity, target lifetime and request generation; obsolete results are discarded. Hide/unmap defers expensive reconciliation; destroy/detach/shutdown fences pending updates. Reflow uses coalesced GUI-thread measurements and re-grids existing widgets; it creates no shadow state or second worker/dispatcher ownership.

Future performance acceptance measures interaction lag and late-result behavior in [ACCEPTANCE.md](ACCEPTANCE.md). Static SVGs cannot demonstrate any of these asynchronous guarantees.
