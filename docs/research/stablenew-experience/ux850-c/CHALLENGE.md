# Method-diverse design consistency challenge

Reviewer: the same primary session, in a separate analytical pass; **not independent review** or an operator study. This focused design challenge reuses A's partial control coverage and B's identity/handoff critique without upgrading either assessment. Its purpose is to falsify the proposed presentation, not establish physical safety or usability.

## Method 1 — competing layout and minimum-case challenge

**Counterproposal:** keep every expert control expanded and preserve a three-column layout at every size. This could reduce disclosure/search cost for frequent operators, and the current app already has many direct controls. A permanently visible guide (N2) could likewise make cross-tab journeys easier.

**Test against the design constraints:** at the conservative 853×453 client, fixed columns compete with baseline source identity, warning and primary action; shrinking typography would violate the proposed readable density. A guide adds another width consumer and must branch correctly for Storyboard Summary, explicit publication/application and source-specific discovery. C instead preserves existing advanced routes, summarizes active hidden values and stacks natural-height sections into a scrolling body. The fixed strip makes the next action discoverable while keyboard focus reveal carries advanced access. This is a falsifiable design choice, not measured superiority.

**Residual:** a 117-unit compact body is small and may require substantial scrolling. Compact wireframes show continuation honestly; no claim that all ordinary fields are visible at once. Actual font/chrome/wrapping can further reduce it. If authorized trials show poor completion/discovery, compare a bounded N2 guide or revise grouping within the existing IDs. Do not adopt a larger unsupported minimum, new persisted journey or toolkit rewrite from this paper result.
